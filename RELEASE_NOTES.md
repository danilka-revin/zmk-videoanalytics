# ZMK Vision v2.18.0 — Живое превью камер на Linux (VP8 WebRTC)

## Проблема

На Ubuntu и других Linux-дистрибутивах веб-превью камеры в браузере **Firefox**
оставалось чёрным. Причина — не в камере и не в go2rtc, а в кодеке:

- Превью шло через MSE/HLS, а go2rtc в этих контейнерах отдаёт **только H.264**.
- Во Firefox на Ubuntu нет H.264-декодера (системный OpenH264/GStreamer обычно
  не установлен), поэтому браузер не мог декодировать поток — карточка была
  чёрной, хотя сам поток с камеры шёл.

## Что изменилось

Теперь браузер получает **VP8** — свободный кодек, который Firefox декодирует
всегда, без установки каких-либо системных пакетов.

### Новый транспорт в go2rtc (`services/go2rtc/go2rtc.yaml`)
- Добавлен шаблон FFmpeg-энкодера `vp8` (`-c:v libvpx`, realtime, low-latency).
- go2rtc перекодирует H.264 камеры в VP8 **только пока за потоком реально
  смотрит браузер** — в простое CPU не расходуется.

### Фронтенд (`frontend/src/main.tsx`)
- Функция `canDecodeH264()` определяет, умеет ли текущий браузер H.264 через MSE.
- Новый WebRTC-транспорт `beginWebRTC()`: signalling через тот же same-origin
  WebSocket `/rtc/api/ws`, медиа — напрямую браузер ↔ go2rtc на порту `8555`.
- Умный выбор транспорта:
  - браузер **без** H.264 (Firefox/Linux) → **WebRTC · VP8**;
  - браузер с H.264 → быстрый **MSE/HLS H.264**;
  - если WebRTC не смог подключиться (NAT/файрвол, нет порта 8555) →
    автоматический **MJPEG**, чтобы карточка никогда не оставалась чёрной.

### Режимы предпросмотра
В форме камеры (и в API) добавлен выбор режима:
- **Авто** (по умолчанию) — браузер сам выбирает кодек (VP8 или H.264);
- **WebRTC · VP8** — принудительно VP8 (работает везде, использует CPU-транскод);
- **MSE · H.264** — прежний быстрый путь для браузеров с H.264;
- **MJPEG** — всегда рабочий fallback.

Поле `preview_mode` в API теперь принимает `auto | mse | webrtc | mjpeg`
(по умолчанию `auto`). База данных мигрируется автоматически (дефолт `auto`).

### Бэкенд (`backend/app/main.py`)
- Новый флаг `GO2RTC_WEBRTC_VP8` (по умолчанию `true`).
- `sync_go2rtc_cameras()` добавляет каждому потоку камеры второй источник
  `src=ffmpeg:{name}#video=vp8` (go2rtc лениво стартует его при первом
  подключении браузера).

### Настройки (`docker-compose.yml`, `.env.example`)
- Новый параметр `GO2RTC_WEBRTC_VP8=true` (проброшен в контейнер API).
- Документация про порт 8555 и настройку VP8.

## Как это работает на проде

1. **Порт 8555 (TCP/UDP)** должен быть доступен браузеру — по нему идёт сам
   медиапоток WebRTC (не через nginx). Если панель открыта удалённо, нужен
   проброс порта. Если порт недоступен — автоматически включится MJPEG.
2. **Проверьте, что в go2rtc есть `libvpx`.** Образ `alexxit/go2rtc:latest`
   (Alpine + `apk add ffmpeg`) собирается с `--enable-libvpx`, так что VP8
   доступен из коробки. Если в вашей сборке его нет — Firefox/Ubuntu уйдёт в
   MJPEG-fallback (работает, но ~15-25 FPS).
3. **Для уже установленных инсталляций:** go2rtc копирует конфиг в `/config`
   только при первом старте. Если там уже лежит старый `go2rtc.yaml`, добавьте
   в него блок `ffmpeg: vp8: ...` (или удалите файл, чтобы подхватился новый
   дефолт), иначе API попытается создать VP8-поток без шаблона и Firefox/Ubuntu
   получит MJPEG.
