# ZMK Vision v2.10.2 — Fix persistent 401 from inference worker

## Симптом

После перехода к авто-токену (v2.10.1) API перестал отдавать `503`, но в логах стало постоянно:
```
GET /api/internal/active-model HTTP/1.1" 401 Unauthorized
```
Камера по-прежнему не обрабатывается (чёрный экран / офлайн).

## Причина

Инфференс-воркер читал токен из `/models/.worker-token` **один раз при старте** и запоминал его навсегда. Если контейнер воркера стартовал **раньше**, чем API успел создать этот файл (а при `docker compose up` контейнеры обычно поднимаются одновременно), воркер считывал пустое значение и потом **всегда** присылал пустой/устаревший токен → API отвечал `401`.

## Решение

Воркер теперь **перечитывает токен при каждом внутреннем запросе** (не кэширует навсегда). Токен лежит в общем томе `model-data:/models/.worker-token`, поэтому:

- неважно, кто стартовал раньше — API или воркер;
- неважно, создал ли API файл после старта воркера;
- согласование всегда происходит «на лету».

Приоритет остаётся: явный `ZMK_WORKER_TOKEN` в env → иначе общий файл.

## Как применить

```bash
# пересобрать и поднять все сервисы (профили inference/training включатся при наличии)
docker compose up -d --build --remove-orphans
docker compose --profile inference up -d --build
```

Если воркер-контейнер старый (без логики перечитывания) — пересборка обязательна; именно этот шаг и даёт эффект.

## Проверки

- Backend **58/58** (добавлен тест «перечитывание поздно созданного токена»), установщики/updater/worker **26/26**, Telegram 3/3, MAX 3/3.
- Ruff, Bandit (прод+updater), tsc/lint, `npm audit` (0), pip-audit (0), shell, compose, `git diff --check` — чисто.
- Логика покрыта юнит-тестами; поведение «порядок старта не важен» подтверждено тестом.

## Параметры

```env
ZMK_WORKER_TOKEN=            # пусто = авто-согласование через общий файл
ZMK_WORKER_TOKEN_FILE=/models/.worker-token
```
