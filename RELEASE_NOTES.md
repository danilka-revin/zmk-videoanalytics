# ZMK Vision v2.5.0 — Training on a ready-made dataset

## Новая возможность: обучение на готовом датасете

Раньше обучение шло только по кадрам, захваченным с RTSP-камеры. Теперь можно обучать модель на **заранее подготовленном датасете** — без камеры вообще.

### Как это работает

1. На вкладке **Модели** в блоке обучения выберите режим **«Готовый датасет»**.
2. Загрузите архив `.zip` датасета в YOLO-формате:
   ```text
   dataset.zip
   ├─ data.yaml        (train / val / names)
   ├─ images/
   │  ├─ train/  *.jpg
   │  └─ val/    *.jpg
   └─ labels/
      ├─ train/  *.txt
      └─ val/    *.txt
   ```
3. Выберите загруженный датасет и нажмите **«Запустить»**.
4. Worker обучает YOLO на вашем датасете (без псевдоразметки и без захвата кадров) и экспортирует ONNX.

### Что реализовано

- `POST /api/datasets` — загрузка zip-датасета, валидация на YOLO-формат (наличие `data.yaml`, списка `names`, минимум 10 изображений), проверка членов архива на path traversal и опасные типы файлов.
- `GET /api/datasets` / `DELETE /api/datasets/{id}` — список и удаление датасетов.
- `training_jobs` получил поля `source` (`camera` | `dataset`) и `dataset_name`; задачи dataset-обучения хранят источник для честного журнала.
- Training worker поддерживает оба источника: камеры (псевдоразметка) и готовый датасет.
- Общий volume `dataset-data` монтируется и в API, и в training worker, поэтому загруженный датасет доступен процессу обучения.
- Web-панель: переключатель «Кадры с камеры / Готовый датасет», загрузка ZIP, список датасетов с числом изображений и классов, удаление.
- Модели, обученные на датасете, помечаются источником `dataset:<имя>`.

### Граница возможностей

Обучение по-прежнему требует реального `training-worker` (Compose profile `training`, NVIDIA GPU желателен). Без него панель честно сообщает, что сервис обучения не подключён. Локальная загрузка и валидация датасета работают всегда.
