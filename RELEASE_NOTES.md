# ZMK Vision v2.6.0 — Security hardening + full re-check

## Закрытые дыры

**1. Path traversal в отдаче/загрузке снимков камеры (важно).**
`GET /api/cameras/{camera_id}/snapshot` строил путь из пользовательского `camera_id` без проверки формата и существования камеры. Теперь:
- `camera_id` валидируется по белому списку символов (`[A-Za-z0-9_-]`, ≤64);
- путь резолвится и жёстко удерживается внутри каталога снимков;
- некорректный id → `400`, корректный, но несуществующий → `404`, существующий снимок → `image/jpeg`.
Единый хелпер `snapshot_path_for` применён в GET, загрузке и удалении — исключён выход за пределы каталога и чтение произвольных файлов.

**2. Zip-бомба / decompression bomb при загрузке датасета (важно).**
`POST /api/datasets` распаковывал архив без лимитов. Добавлен контроль перед извлечением и во время него:
- лимит числа файлов (15000) и распакованного объёма (2 ГБ), лимит одного файла (1 ГБ);
- отклонение симлинков, устройств и опасных типов файлов (`.sh`, `.exe`, `.bat`, `.cmd`, `.ps1`);
- почленное безопасное извлечение со счётчиком распакованных байт.
Превышение → `413` с понятным сообщением.

## Дополнительно проверено

- **SQL-инъекции:** все запросы параметризованы — ок.
- **CSV-инъекция:** экранирование формул в экспортах — присутствует.
- **XSS:** фронтенд на React (экранирует по умолчанию), `dangerouslySetInnerHTML`/`innerHTML`/`eval` отсутствуют.
- **SSRF:** `webhook_url` допускает только `http(s)://`; RTSP-URL камер допускают `rtsp(s)://` — ожидаемо для встраиваемых камер.
- **Секреты:** `.env` и ключи исключены из git; в `.env.example` только плейсхолдеры; приватные ключи не в репозитории.
- **Аутентификация:** `X-API-Key` (constant-time), worker-токен на `/api/internal/*`, роли admin/operator/viewer у ботов и Telegram Mini App (HMAC initData) — ок.
- **Инференс-шлюз:** валидация bbox, timestamp, камеры, порогов, идемпотентность по `detection_id` — ок.
- **Обновление из панели:** эндпоинты защищены `ZMK_UPDATE_TOKEN`, API-сервис слушает только `127.0.0.1`.

## Примечание

Контейнеры пока запускаются от root — это осознанный компромисс: переход на не-root сломает запись в host-биндовые томы (`./data`, `DATASET_DIR`). Отмечено для следующего этапа.
