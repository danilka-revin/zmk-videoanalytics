# ZMK Vision v2.19.0 — Пользователи панели с ролями и смена аккаунта как в Steam

## Проблема

В панель можно было войти только под двумя жёстко зашитыми аккаунтами —
`admin` и `director`. Роль «директор» была одна на всех: человек, который
разбирает очередь детекций, и человек, которому нужно просто посмотреть
инфографику, получали одинаковый доступ. Добавить аналитика, оператора смены
или гостя было нельзя — только общий пароль.

Смена пользователя при этом закрывала панель entirely: интерфейс гас, вместо
него показывалась заглушка, и было непонятно, под кем ты сейчас вошёл.

Отдельно выяснилось, что размытие интерфейса не работало в Firefox: минификатор
CSS выбрасывал свойство `backdrop-filter`, если перед ним в том же блоке стоял
`-webkit-backdrop-filter`.

## Что изменилось

### Пользователи и роли

Аккаунты панели переехали из конфига в таблицу `auth_accounts`
(`login`, `label`, `role`, `password_hash`, `active`, `built_in`). На свежей
базе создаются два встроенных аккаунта — `admin` и `director`; остальных
администратор создаёт сам.

Три роли:

| Роль | Что может |
| --- | --- |
| **Администратор** (`admin`) | Всё, включая управление пользователями |
| **Аналитик** (`analyst`) | Аналитика, камеры, события; **принимает и отклоняет детекции**, в том числе пакетами |
| **Гость** (`viewer`) | Только просмотр инфографики, камер и событий |

Права проверяются на каждый запрос (`_role_request_allowed`), поэтому:

- смена роли применяется к уже открытым сеансам сразу, без перезахода;
- сброс пароля и отключение аккаунта мгновенно завершают его сеансы;
- отключённый аккаунт не может войти (`401`), а его живой сеанс теряет доступ
  (`401`) уже на следующем запросе.

Запреты: встроенного `admin` нельзя разжаловать, отключить или удалить;
отключить или удалить собственный аккаунт тоже нельзя. Неизвестный логин
отвечает `401`, как неверный пароль, — по ответу нельзя угадать существующие
логины (раньше такая попытка отдавала `422`).

### API

Новые эндпоинты, доступные только администратору:

```
GET    /api/auth/accounts            список аккаунтов + список ролей
POST   /api/auth/accounts            создать (login, label, role, password)
PUT    /api/auth/accounts/{login}    имя, роль, пароль, active
DELETE /api/auth/accounts/{login}    удалить
```

`GET /api/auth/status` теперь отдаёт `accounts` (с флагом `current`), `roles`,
`login`, `label` и `role`; `GET /api/auth/sessions` — `login`, `label` и `role`
каждого сеанса.

Вход под другим аккаунтом в том же браузере **закрывает прежний сеанс** — это
делает сервер внутри `POST /api/auth/login`, потому что у нового аккаунта может
не быть прав удалять чужие сеансы. Повторный вход под тем же аккаунтом, как и
раньше, просто добавляет ещё один валидный сеанс.

### Фронтенд

- **Персонализация → Доступ → Пользователи панели** — менеджер аккаунтов:
  создание, переименование, смена роли, сброс пароля, отключение, удаление.
  Роль выбирается из списка, полученного с сервера, с подсказкой о правах.
- **Смена пользователя** (кнопка в шапке и в блоке профиля слева) больше не
  закрывает панель: список аккаунтов и окно пароля открываются **поверх
  работающего интерфейса**, который остаётся слегка размытым. Есть
  «Отмена · остаться в панели» и «Выйти из системы».
- **Текущий аккаунт помечен как в Steam**: аватар с инициалами, имя, роль,
  зелёная метка «Текущий», а в списке — флаг «Вы вошли». Остальные аккаунты
  показаны списком ниже.
- Список аккаунтов перечитывается при каждом открытии переключателя: только что
  созданный или отключённый пользователь виден сразу, без перезагрузки страницы.
- Разделы панели выводятся из роли: у администратора 8 разделов, у аналитика и
  гостя — «Обзор», «Камеры», «События». У аналитика кнопки принятия/отклонения
  активны, у гостя очередь доступна только на просмотр.

### Размытие в Firefox (и везде)

Пары `backdrop-filter` / `-webkit-backdrop-filter` в стилях переписаны в порядке
«префикс первым, стандартное свойство последним» — именно в таком порядке
минификатор сохраняет оба. В собранном CSS число стандартных `backdrop-filter`
выросло с **8 до 24**: размытие теперь работает не только в Chrome и Safari, но
и в Firefox, причём не только у переключателя аккаунтов, но и у остальных
«стеклянных» поверхностей панели.

## Как это работает на проде

1. **Миграция не нужна.** Таблица `auth_accounts` создаётся при старте, туда же
   переносятся пароли `admin` и `director` из настроек. Уже заданные владельцем
   пароли не перезаписываются.
2. **Переменные окружения не изменились:** `ZMK_INITIAL_PASSWORD` (по умолчанию
   `admin`) и `ZMK_DIRECTOR_PASSWORD` (по умолчанию `director`) задают стартовые
   пароли встроенных аккаунтов на свежей базе.
3. **Первый вход** — под `admin`, дальше людей добавляете в
   Персонализация → Доступ. Пароль каждого созданного пользователя задаётся
   сразу при создании; сбросить его можно там же.
4. **Отпуск/увольнение** — аккаунт отключается одной кнопкой, его сеансы
   завершаются немедленно; удалять не обязательно.

## Быстрая проверка

```bash
./start.sh
# 1. войти как admin / admin
# 2. Персонализация -> Доступ -> Пользователи панели: создать «Аналитика»
# 3. «Сменить пользователя» в шапке: панель остаётся открытой и размывается,
#    текущий аккаунт помечен меткой «Текущий» / «Вы вошли»
# 4. войти под аналитиком: 3 раздела, события принимаются и отклоняются,
#    настроек нет
```
