# ZMK Vision v2.20.0 — Запуск больше не зацикливается на сборке web (npm ci)

## Проблема

При `./start.sh` стек зависал на шаге сборки образа **web**: Docker-стадия
`RUN npm ci` (шаг `[web build 4/6]`) уходила в бесконечное ожидание без какого-либо
вывода. `registry.npmjs.org` медленный или недоступен из части сетей (частый
случай для RU/CN), а `npm` по умолчанию тихо висит на мёртвом соединении. Пока
npm «молчал», старт прерывали (CANCELED) и запускали заново — `start.sh` начинал
пересборку с того же места, и так бесконечно.

Дополнительно каждый обычный запуск принудительно пересобирал **все** образы
(`up -d --build`), то есть снова и снова гонял web-стадию `npm ci` по сети даже
тогда, когда код с прошлого раза не менялся.

## Что изменилось

### web-сборка больше не висит молча (frontend)

- Добавлен `frontend/.npmrc` с устойчивыми настройками npm: `fetch-retries`,
  `fetch-retry-*`, `fetch-timeout=60000`, `prefer-offline=true`. npm теперь
  быстро определяет недоступный реестр и прозрачно повторяет разовые сбои,
  вместо того чтобы бесконечно ждать без вывода.
- `frontend/Dockerfile`:
  - `.npmrc` копируется до установки зависимостей;
  - `npm ci` идёт с `--no-audit --no-fund` (меньше шума и лишних сетевых шагов);
  - добавлен build-арг **`NPM_REGISTRY`** — при его задании npm переключается
    на ваш зеркальный реестр (например `https://registry.npmmirror.com`);
  - npm-кэш очищается после установки, чтобы не раздувать слой образа.
- `docker-compose.yml` пробрасывает `NPM_REGISTRY` из `.env`
  (`web.build.args`), `.env.example` задокументирован.

### Быстрый запуск без принудительной пересборки (start.sh)

- Новый режим **`./start.sh --fast`** (или `ZMK_FAST=1`): запускает стек на уже
  собранных образах (`up -d` без `--build`), не трогая сеть для `npm ci`.
  Compose сам достроит только те образы, которых ещё нет. Это то, что нужно
  после ребута/остановки, когда код не менялся, и мгновенный способ выйти из
  зацикленной пересборки.
- После реального обновления кода запуск по-прежнему делается обычным
  `./start.sh` (полная пересборка с учётом кэша).

## Как применить

Обновитесь до `v2.20.0` обычным способом (auto-update или `git pull`), затем:

```bash
./start.sh            # один раз пересобрать стек с новыми правилами сборки
```

Если на шаге web снова почувствуете зависание npm — задайте в `.env` зеркало
и повторите:

```
NPM_REGISTRY=https://registry.npmmirror.com
```

А когда код уже обновлён и нужен просто перезапуск сервисов — используйте
быстрый режим, чтобы не пересобирать всё заново:

```bash
./start.sh --fast
```
