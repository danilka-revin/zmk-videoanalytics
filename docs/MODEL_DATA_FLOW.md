# Передача данных от модели к системе

## Контракт

Inference worker отправляет пакет в `POST /api/inference/detections`:

```json
{
  "detections": [{
    "camera_id": "cam_01",
    "model_name": "siz-guard-v2.1",
    "timestamp": "2026-08-19T14:30:00+07:00",
    "event_type": "no_helmet",
    "confidence": 0.94,
    "person_id": "P-1024",
    "detection_id": "cam_01-frame_938-person_2-no_helmet",
    "bbox": [120, 80, 430, 710]
  }]
}
```

Gateway для каждой детекции проверяет:

1. Pydantic-схему и допустимый тип события.
2. Совпадение `model_name` с primary-моделью или одним из атомарно назначенных специализированных слотов. Старые workers и модель, снятая со слота, получают `stale_model`.
3. Существование камеры, online-состояние и флаг AI.
4. Индивидуальный порог confidence для каждого типа события.
5. Корректность bbox и допустимое окно timestamp: не старше 7 дней и не более чем на 10 минут в будущем.
6. Идемпотентность по `detection_id`: повторная доставка возвращает существующий `event_id`, не создавая дубль.
7. Классификацию severity и запись события в БД.
8. Audit log всего batch с количеством принятых и отклонённых детекций.

Чтение active primary-модели и специализированных слотов, а также запись batch выполняются в одной транзакции, поэтому hot-swap или перестановка слота не может разорвать обрабатываемый пакет. Ответ содержит `event_id` для принятых событий и причину для каждого отклонения. Событие сразу доступно в `/api/events`, отчётах и панели.

## Мульти-модельный контур

В **Модели → Отдельные модели по задачам** можно независимо назначить production-модели в слоты:

- `people` — люди;
- `helmet` — каски / `no_helmet`;
- `workwear` — спецодежда / `no_vest`;
- `phone` — телефон;
- `smoking` — курение;
- `zone` — опасные зоны.

Worker запускает назначенные модели отдельно на одном и том же кадре, объединяет реальные боксы для overlay и передаёт происхождение каждой детекции через `model_name`. Связка `people` + `helmet` может осторожно сформировать `no_helmet`, если helmet-модель объявляет класс `helmet`; отсутствие жилета намеренно требует явного класса `no_vest`, чтобы не превратить перекрытую одежду в ложную тревогу. Production-слот принимает только модель с Precision/Recall, прошедшими quality gate.

## Production transport

HTTP-контракт является каноническим. При масштабировании тот же JSON публикуется worker-ом в Redis Streams, consumer вызывает тот же validation/service слой. Для гарантированной доставки используются consumer groups, idempotency key и dead-letter stream; это следующий production-этап после подключения реальных RTSP и GPU worker.
