# Хостинг Zovod дома — ноутбук с Debian как сервер

Домен **maisaak-3dprintlab.online**, пароли, CORS и HTTPS уже вшиты в проект
(`deploy.env` + Caddy с бесплатными сертификатами Let's Encrypt). От VPS
домашний хостинг отличается только одним: ноутбук стоит **за роутером**,
поэтому к шагам добавляются проброс портов и DNS на ваш домашний IP.

Весь путь — **3 шага**. На ноутбуке всё делают два скрипта, руками остаются
только роутер и панель reg.ru (по 2–5 минут, делается один раз).

| Что | Где делается | Чем |
|---|---|---|
| Docker, запрет сна, автозапуск, файрвол, подсказки по IP | ноутбук | `sudo bash setup-home.sh` |
| Сборка и запуск всего стека + применение `deploy.env` | ноутбук | `./start.sh --no-open` |
| Проброс портов 80, 443, 8555 | роутер | руками, 1 раз |
| A-записи домена на ваш внешний IP | панель reg.ru | руками, 1 раз |

---

## Шаг 1. Ноутбук (две команды)

```bash
# если проекта ещё нет на ноутбуке:
sudo apt update && sudo apt install -y git
git clone https://github.com/danilka-revin/zmk-videoanalytics.git ~/zmk-videoanalytics
cd ~/zmk-videoanalytics

# доводка ноутбука под сервер (одна команда, повторять не нужно):
sudo bash setup-home.sh

# сборка и запуск (первый раз 5–20 минут; мастер спросит про ботов —
# можно выбрать «без бота», всё настраивается позже в Админ → Боты):
./start.sh --no-open
```

Что сделает `setup-home.sh`:

- поставит Docker + Compose и включит их автозапуск при загрузке —
  после перезагрузки ноутбука сайт поднимется **сам**, без команд
  (контейнеры помечены `restart: unless-stopped`);
- отключит сон и гибернацию — **крышку можно закрывать**, сервер работает;
- отключит nginx/apache, если они занимают 80/443 (их заменяет Caddy);
- откроет порты в ufw (если он установлен);
- покажет **локальный IP ноутбука** (нужен для шага 2) и **внешний IP**
  (нужен для шага 3), сверит их с DNS и предупредит про CGNAT.

`./start.sh` при каждом запуске сам переносит `deploy.env` в `.env`
(домен, пароли `admin`/`director` = `72327232`), так что после обновлений
проекта достаточно снова запустить `./start.sh` — больше ничего.

## Шаг 2. Роутер (один раз, ~3 минуты)

Зайдите в веб-панель роутера (обычно `192.168.0.1` или `192.168.1.1`) и в
разделе «Переадресация портов» / «Port Forwarding» / «Виртуальные серверы»
пробросьте на **локальный IP ноутбука** (его напечатал `setup-home.sh`):

| Внешний порт | Протокол | Куда | Зачем |
|---|---|---|---|
| 80 | TCP | IP ноутбука : 80 | выпуск HTTPS-сертификата, редирект на https |
| 443 | TCP + UDP | IP ноутбука : 443 | сам сайт |
| 8555 | TCP + UDP | IP ноутбука : 8555 | живое видео камер (WebRTC) |

Там же **закрепите IP за ноутбуком** («DHCP reservation» / «привязка по
MAC»), чтобы после перезагрузки роутера проброс не «уехал» на другой адрес.

> **Проверка на CGNAT (важно!).** Посмотрите в панели роутера его WAN-IP.
> Если он **не совпадает** с внешним IP из `setup-home.sh` (или начинается
> на `100.64`–`100.127`, `10.`, `172.16`–`172.31`, `192.168`) — провайдер
> держит вас за CGNAT, и никакой проброс портов не поможет. Решение:
> позвонить провайдеру и подключить услугу **«белый (публичный) IP»** —
> обычно 100–200 ₽/мес, включают за минуты.

## Шаг 3. DNS на reg.ru (один раз, ~2 минуты)

**«Мои домены» → maisaak-3dprintlab.online → Управление DNS-записями.**
Замените значения A-записей на ваш **внешний IP** (его напечатал
`setup-home.sh`, либо `curl ifconfig.me` на ноутбуке):

| Тип | Имя | Значение | TTL |
|---|---|---|---|
| `A` | `@` | ваш внешний IP | 600 |
| `A` | `www` | ваш внешний IP | 600 |

TTL 600 (10 минут) удобен для дома: если провайдер сменит вам IP, после
исправления записи сайт вернётся быстро. Обновление DNS — от минуты до часа.
Проверка: `ping www.maisaak-3dprintlab.online` должен показать ваш IP.

## Готово

- Сайт: **https://www.maisaak-3dprintlab.online** (и без `www`);
- Вход: **admin / 72327232** (полный доступ), **director / 72327232** (просмотр);
- HTTPS-сертификат Caddy выпустит сам в первые минуты после того, как DNS
  и порт 80 заработают. Если не выпустился: `docker compose restart caddy`.

## Повседневная жизнь сервера (минимум телодвижений)

| Ситуация | Что делать |
|---|---|
| Перезагрузили/включили ноутбук | **Ничего** — Docker и стек стартуют сами |
| Закрыли крышку | **Ничего** — сон отключён, сервер работает |
| Обновить проект до новой версии | `./start.sh` (сам скачает и пересоберёт) |
| Остановить сайт | `docker compose down` в папке проекта |
| Запустить снова | `./start.sh --fast` (без пересборки — быстро) |
| Посмотреть логи | `docker compose logs -f --tail=100` |
| Сбросить пароли всем | `bash set-passwords.sh` |

Рекомендации для ноутбука-сервера:

- держите его **на зарядке** и по возможности **на проводе** (Ethernet);
  если только Wi-Fi — закрепите IP на роутере (уже сделано в шаге 2);
- в BIOS включите **Restore on AC Power Loss** — после отключения света
  ноутбук включится сам (батарея ноутбука при этом работает как мини-UPS);
- данные (`./data`, Docker volumes) живут на ноутбуке — время от времени
  копируйте папку `data/` на флешку/другой диск.

## Если у провайдера динамический IP

Домашний внешний IP может иногда меняться (обычно при перезагрузке роутера
или раз в несколько дней/недель). Симптом: сайт перестал открываться, а
`curl ifconfig.me` на ноутбуке показывает не тот IP, что в A-записях.

Варианты от простого к сложному:

1. **Белый статический IP у провайдера** — лучший вариант, одна услуга
   решает и CGNAT, и смену адреса. Настроил и забыл.
2. **Руками**: при смене IP зайти на reg.ru и поправить две A-записи
   (при TTL 600 сайт вернётся за ~10 минут). При редких сменах IP этого
   достаточно.
3. **Автоматически (DDNS)**: включить у reg.ru доступ к API и крон-скриптом
   обновлять A-записи при смене IP (методы API `zone/remove_record` +
   `zone/add_alias`, нужно разрешить свой IP в настройках API reg.ru).
   Настраивайте, только если IP реально меняется часто.

## Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| Сайт не открывается снаружи, но работает по `http://IP-ноутбука:5173` из домашней сети | Не сделан/не сработал проброс портов (шаг 2) или CGNAT. Проверьте снаружи (с телефона через мобильный интернет, не Wi-Fi) |
| `ping домена` показывает чужой/старый IP | DNS ещё не обновился или A-записи не исправлены (шаг 3) |
| Сертификат не выпускается, в логах Caddy ошибки ACME | Порт 80 снаружи закрыт (проброс/CGNAT) или DNS ещё указывает не туда. Исправить и `docker compose restart caddy` |
| Открывается по домену, но видео с камер нет | Не проброшен порт 8555 TCP+UDP |
| После перезагрузки сайт не поднялся | `systemctl status docker` → `sudo systemctl enable --now docker`, затем `./start.sh --fast` |
| Ноутбук уснул при закрытой крышке | Повторить `sudo bash setup-home.sh` и перезагрузиться (настройки logind применяются гарантированно после ребута) |
